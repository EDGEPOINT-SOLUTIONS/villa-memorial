# Business Model Flexibility

## Models the platform must support (module activation, not rewrites)
| Model | Composition |
|---|---|
| **A** | Funeral home + chapel + embalming + coffin sales |
| **B** | Funeral home + memorial park + burial lots |
| **C** | Memorial park + chapel + crematorium |
| **D** | Funeral-service chain, multiple branches |
| **E** | Independent funeral home, limited services |
| **F** | Integrated group: homes, chapels, embalming, transport, coffins, cremation, memorial lots, cemetery, park, pre-need + at-need |

Administrators activate/deactivate modules and configure available services.

## Transaction types (Villa blueprint §9.1)
| Type | Purpose | Examples |
|---|---|---|
| **At-Need Order** | Immediate service/product purchase | Embalming + chapel + hearse; casket only; chapel only |
| **Pre-Need Contract** | Future memorial benefit purchased in advance | Traditional plan payable over time |
| **Memorial Property Transaction** | Reservation/purchase/ownership lifecycle | Family lot, garden lot, columbarium niche |
| *(4th pattern)* **Service-Only** | No plan, no lot — buys independent services | Any single service |

**Commercial rule**: a customer does NOT need a pre-need plan to buy. Everything independently
sellable unless explicitly package-only. Lots purchasable independently of plans. Mixed carts of
heterogeneous item types must produce correct downstream operational records.

## Service catalog classes (blueprint §6.1)
PRODUCT (physical) · SERVICE (work) · RENTAL/RESOURCE (bookable) · TIME-BASED SERVICE ·
TRANSPORT SERVICE · FIELD SERVICE · PROPERTY · MEMORIAL LOT (specialized: GIS+ownership+interment) ·
PACKAGE (bundle) · PLAN (pre-need contractual) · ADD-ON · QUOTE-REQUIRED ITEM.
